01 / Motivation

Less black box.
More creative control.

Automated code generation is useful, but a successful workflow should also make it easy to understand what happened and decide what happens next.

× The challenge

Automation without visibility

Opaque generation-and-repair loops can make it difficult to inspect intermediate code, adjust imperfect tests, or redirect a repair when the developer knows more about the requirement.

Prompt→?→Code
✦ The AdaAssist approach

Automation with checkpoints

Expose generated code, test results, and repair plans in a stateful workflow. Let developers revise artifacts or offer guidance before regeneration continues.

Generate→Evaluate↔Intervene

02 / Under the hood

An adaptive, four-agent workflow.

Each agent has a clear responsibility. AdaAssist starts with direct generation, uses lightweight fixes for supported errors, and escalates to plan-guided regeneration when deeper problems remain.

03 / Developer experience

One tool.
Two ways to work.

Stay hands-off when the task is straightforward. Step in when tests, generated code, or a repair plan need human judgment. Modes can be changed at supported checkpoints.

HUMAN-IN-THE-LOOP

Pause at the moments that matter.

Review generated tests, inspect a candidate, adjust repair plans, and guide the next generation step with your own expertise.

  • Inspect and edit intermediate artifacts
  • Refine public tests and requirements
  • Resume the same session after review

04 / Research

Designed for human + AI collaboration.

The AdaAssist manuscript investigates both the backend's adaptive generation process and the effect of developer controls on perceived understanding and code repair.

FROM THE MANUSCRIPT · USER STUDY

Transparency changes how people experience programming assistants.

In a 20-participant user study, Interactive received a higher mean understandability rating than Auto. Ratings reflect participant perceptions, not a guarantee of program correctness.
